# How to Test Glassflow Agents

## 🎯 Quick Answer

**For best results: Use Pipeline mode!** 🎬

But if you want to test individual agents, here's how:

---

## 🤔 Understanding Agent Dependencies

```
🏗️ Architect (Independent)
    ↓ produces architecture plan
⚙️ Engineer (Needs Architect's plan)
    ↓ produces code files
✅ Quality (Needs Engineer's code)
    ↓ produces quality-checked code
🐛 Debug (Needs Quality's code)
    ↓ produces tested code
✨ Production-Ready Code!
```

---

## 📝 What to Enter for Each Agent

### 🏗️ Architect (Always Works Standalone)

**What to enter:**
```
Build a todo app with React and TypeScript.
Use Zustand for state management.
Include add, delete, and toggle functionality.
```

**What you'll see:**
- Requirements identified
- Ambiguities detected
- Architecture decisions
- Confidence score

**Why it works:** Architect only needs your description!

---

### ⚙️ Engineer (Best in Pipeline Mode)

**Standalone testing:**
- Leave input field as-is (disabled)
- Click "Test Engineer Agent"
- Uses a mock architecture plan
- Shows it can generate code

**What you'll see:**
- Mock plan details
- Files that would be generated
- Note about using Pipeline mode

**For real code generation:** Use Pipeline mode!

**Why:** Engineer needs a real architecture plan from Architect. In standalone mode, it uses a simplified mock plan just to show it works.

---

### ✅ Quality (Works Standalone with Code)

**What to enter (optional):**
```typescript
const App = () => {
  const data = await fetch('/api/data');
  return <div dangerouslySetInnerHTML={{__html: data}} />;
};
```

**Or leave empty** to use default test code with intentional issues.

**What you'll see:**
- Security issues detected (XSS vulnerability)
- Code quality problems
- Auto-fixes applied
- Confidence score

**Why it works:** Quality can analyze any code you give it!

---

### 🐛 Debug (Works Standalone with Code)

**What to enter (optional):**
```typescript
const App = () => {
  const data = await fetch('/api/data');
  return <div>{data.title}</div>;
};
```

**Or leave empty** to use default test code with runtime bugs.

**What you'll see:**
- Runtime tests executed
- Bugs detected (null pointer, missing error handling)
- Auto-fixes applied
- Test results

**Why it works:** Debug can test any code you give it!

---

### 🎬 Pipeline (Recommended!)

**What to enter:**
```
Build a todo app with React and TypeScript.
Use Zustand for state management.
Include add, delete, and toggle functionality.
```

**What you'll see:**
- All 4 agents running in sequence
- Architect analyzes your spec
- Engineer generates code
- Quality reviews the code
- Debug tests the code
- Complete production-ready output!

**Why it's best:** All agents work together with real data!

## 💡 Common Questions

### Q: Why does Engineer say "use Pipeline mode"?
**A:** Engineer needs a real architecture plan from Architect. In standalone mode, it uses a mock plan just to show it works. For real code generation, use Pipeline mode where Architect → Engineer work together.

### Q: What should I enter for Quality and Debug?
**A:** You can:
- **Leave empty** - Uses default test code with intentional bugs
- **Enter your own code** - Tests your specific code
- **Use Pipeline mode** - Tests code generated by Engineer

### Q: Why does input clear when I switch agents?
**A:** Each agent needs different input! Architect needs a spec, Quality needs code, etc. The input clears so you start fresh with the right type of input for each agent.

### Q: Can I see previous results?
**A:** Yes! The output stays visible when you switch agents. Use the "Clear" button if you want to reset everything.
